# 🌐 범용 웹 데이터 수집·EDA·대시보드 구축 운영 표준 규칙

본 규칙은 임의의 신규 사이트(E-commerce, 포털, 채용, 부동산, 미디어 등)를 대상으로 데이터를 수집하고, 전문적인 데이터 분석 리포트를 작성하며, 인터랙티브 웹 대시보드를 배포할 때 반드시 준수해야 하는 엔드투엔드 표준 가이드라인입니다.

---

## 1. 프로젝트 폴더 및 환경 격리 원칙

1. **공통 가상환경 원칙**:
   - 워크스페이스 루트의 단일 `.venv`만 공통으로 사용합니다.
   - 새 사이트 프로젝트를 추가할 때 별도의 가상환경을 생성하지 않습니다.
   - 모든 패키지 설치와 실행은 반드시 `uv`를 기준으로 진행합니다. (예: `uv run python ...`, `uv pip install ...`)
   - `conda`, `poetry`, `pipenv`, `virtualenv`, `python -m venv`는 절대 사용하지 않습니다.

2. **5대 필수 표준 디렉터리 자동 생성**:
   - 신규 사이트 프로젝트(예: `site_name/`)를 시작할 때 하위에 반드시 다음 5개 폴더를 자동으로 생성합니다:
     - `data/`: 수집된 원천 데이터 파일 (CSV, JSON 등) 저장
     - `src/`: 스크래퍼, EDA 스크립트, 대시보드 빌더 등 소스 코드 저장
     - `images/`: 고해상도 시각화 차트 이미지(.png) 저장
     - `docs/`: 수집 계획서, API 명세서, 아티팩트 문서 저장
     - `reports/`: 최종 전문 데이터 분석 종합 보고서(.md) 저장

3. **상대경로 준수**:
   - 특별한 시스템 제약이 없는 한 모든 코드, 스크립트, 마크다운 링크에서 워크스페이스 내부 상대경로를 사용합니다.

## 2. 데이터 수집(크롤링) 3단계 전략

1. **1순위 (최우선): 프론트엔드 내부 REST / GraphQL Gateway API 역공학**:
   - 웹 브라우저를 무겁게 띄우기 전에 개발자 도구(Network 탭) 트래픽을 분석하여 공식 프론트엔드가 호출하는 내부 API 엔드포인트와 쿼리 파라미터를 먼저 발굴합니다.
   - 불필요한 차단 위험을 회피하고 초고속으로 수집합니다.
2. **2순위: 정적 HTML 파싱 (`urllib` / `requests` + `BeautifulSoup`)**:
   - API가 없는 정적 웹페이지의 경우 가벼운 HTTP 클라이언트로 HTML을 다운로드하여 정규식 및 파서로 추출합니다.
3. **3순위: 동적 CSR 및 봇 탐지 우회 시 브라우저 자동화 (`Playwright`)**:
   - 복잡한 자바스크립트 렌더링, 캡차, 인터랙션이 요구되는 경우에 한하여 Playwright 헤드리스 브라우저를 구동합니다.
4. **수집 무결성 및 저장 규격**:
   - 서버 부하 방지를 위해 요청 간 최소 0.5초 대기(`time.sleep(0.5)`)를 의무화합니다.
   - GZIP 응답(`0x1f 0x8b`) 압축 해제 및 텍스트 내 HTML 태그 정제를 반드시 수행합니다.
   - 저장 포맷은 엑셀 호환을 위해 **`UTF-8-SIG`** 인코딩의 CSV로 저장하며, 파일명은 `{site}_daily_{category}_{YYYYMMDD}.csv` 형태를 따릅니다.
   - 수집 완료 후 전체 건수, 결측치율(0% 목표), 순위 연속성을 자동 검증합니다.

## 3. 심층 탐색적 데이터 분석(EDA) 원칙

1. **기본 데이터 파악 필수 출력**:
   - 상위 5개 행(`head()`)과 하위 5개 행(`tail()`) 출력
   - 전체 데이터 크기(행 수, 열 수), 결측치 통계, 중복 행 수(`df.duplicated().sum()`) 명시
2. **기술통계 및 2,000자 이상 심층 인사이트**:
   - 수치형 변수(`describe()`)와 범주형 변수(`describe(include=['object'])`) 기술통계 산출
   - 각 기술통계표 하단에 단순 수치 나열을 넘어 시장 구조, 소비자 심리, 가격 형성 메커니즘을 분석하는 **최소 2,000자 이상의 비즈니스 인사이트**를 필수 작성합니다.
3. **시각화 공통 스타일 제약**:
   - Seaborn 전역 스타일(`sns.set_theme()`, `sns.set_style()`) 설정은 절대 금지합니다.
   - 한글 폰트 깨짐 방지를 위해 `import koreanize_matplotlib`를 필수로 적용합니다.
4. **텍스트 마이닝**:
   - 형태소 분석기(KoNLPy 등)는 설치/실행 지연으로 사용하지 않으며, `scikit-learn`의 `TfidfVectorizer`를 사용하여 상위 30대 핵심 키워드 가중치를 도출하고 가로 막대 그래프와 매핑 표를 병행 출력합니다.
5. **시각화 차트 10종 이상 생성**:
   - 일변량, 이변량, 다변량 차트를 균형 있게 최소 10개 이상 생성하여 `images/` 폴더에 고해상도(DPI 150) PNG로 저장합니다.
   - 모든 차트 하단에는 요약 통계표(교차표, 피봇테이블)와 **200자 이상의 해석**을 기재합니다.
6. **최종 리포트 발행**:
   - 모든 분석 결과를 집대성하여 `reports/EDA_Report.md` 파일로 작성합니다.

## 4. 인터랙티브 웹 대시보드 구축 원칙

1. **독립형 단일 파일(Single File HTML) 아키텍처**:
   - 별도의 백엔드 서버 없이 브라우저에서 로컬 파일(`file://`)로 더블클릭해도 CORS 오류 없이 즉시 동작하도록, 정제된 전수 데이터를 JSON으로 인라인 임베드합니다.
2. **글래스모피즘(Glassmorphism) UI 시스템**:
   - 앰비언트 글로우(Ambient Glow) 오로라 원형 배경 블러 애니메이션 적용
   - 반투명 블러 패널(`backdrop-filter: blur(20px)`), 은은한 화이트/슬레이트 테두리(`border: 1px solid rgba(...)`)
   - 사용자 선호에 따라 화이트 글래스모피즘(White Glassmorphism) 또는 다크 글래스모피즘(Dark Glassmorphism) 테마를 일관되게 적용합니다.
3. **Chart.js v4 기반 6대 핵심 시각화**:
   - 분포, 점유율, 시계열 추이, 다변량 관계 등 6개 이상의 차트를 반응형으로 배치합니다.
4. **실시간 데이터 탐색기**:
   - 실시간 텍스트 검색, 다중 조건 필터, 테이블 컬럼 클릭 정렬, 반응형 페이지네이션, 상세 모달 팝업, 필터링 결과 CSV 다운로드 기능을 기본 탑재합니다.

## 5. Git 워크플로우 및 자동 배포 원칙

1. 기능 개발 시 `feat/{site}-{feature}` 명명 규칙의 브랜치를 생성합니다.
2. 작업 내역을 명확한 커밋 메시지(Conventional Commits)로 작성하여 원격 저장소에 푸시합니다.
3. GitHub API를 통해 Issue 생성 및 Pull Request를 제출하여 메인 브랜치와 병합합니다.
4. 완성된 웹 대시보드는 `gh-pages` 브랜치를 통해 GitHub Pages 라이브 웹앱(`https://{user}.github.io/{repo}/`)으로 온라인 공개 배포합니다.
